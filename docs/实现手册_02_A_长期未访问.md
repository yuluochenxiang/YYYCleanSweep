## 二、关键技术背景（理解才不会写歪）

### 2.1 什么是 atime

`os.stat()` 返回的 `st_mtime` 是**最后修改时间**（内容变了才更新），
`st_atime` 是**最后访问时间**（打开过就更新）。

清理磁盘时，「几年没打开过的东西」比「几年没改过的东西」更有参考价值——
因为复制、备份、迁移会整批改写 mtime，但不会让人真的去打开它。

### 2.2 ⚠️ Windows 的坑（必须处理，否则整列没意义）

Windows 上 `st_atime` **可能根本不更新**（NTFS 的 `NtfsDisableLastAccessUpdate` 策略，
历史上不同版本的默认值不一样）。表现是：atime 停在文件创建那一刻，甚至**早于 mtime**。

所以必须兜底：

```python
at = st.st_atime
mt = st.st_mtime
if at + 1.0 < mt:      # 访问时间早于修改时间 = 系统压根没记，用 mtime 兜底
    at = mt
```

**绝不允许显示空白或 1970 年这种值。**

另外一个可靠性判断：如果整棵树里**从来没有**出现过 `atime > mtime + 3600` 的文件，
说明这台机器大概率没开访问时间记录，界面上要如实告诉用户（见 Step 8）。

### 2.3 几乎零成本

`core/dirstat.py` 的 `_scan_one()` 本来就要对每个文件 `e.stat()` 取 size 和 mtime，
`stat` 结果里**已经带着 `st_atime`**，多读一个字段不产生任何额外系统调用。
不要为此再写一遍遍历。
