## 二、四个必须先想清楚的设计决策

### 2.1 只支持 zip / tar，rar 和 7z 明确不支持

标准库搞不定 rar / 7z。硬做要引 `py7zr` / `rarfile` 之类的库，
带来的就是几 MB 的包体增长 —— **碰红线（总纲红线 1）**。

所以策略是：**不支持就直接说不支持**，返回一个带 `error` 的结果，
界面显示一句人话。千万不要让它抛异常、更不要返回空无一物的区域让用户猜。

### 2.2 只读清单，不解包、不落盘

`zipfile` 的 `infolist()` 读的是**末尾的中央目录**，不需要解压任何数据；
`tarfile` 虽然要顺序扫一遍文件头，但也只读头信息，不写任何临时文件。

这条要保证：**本卷不产生任何临时文件**，也不写 `%TEMP%`。

### 2.3 🔴 tar 要设体积上限，zip 不用

这是两种格式的本质差别：

| 格式 | 读清单的代价 |
| --- | --- |
| zip | 只读末尾中央目录，**无论多大都很快** |
| tar / tar.gz | 流式格式，**要把整个文件从头过一遍** |

一个 20 GB 的 `.tar.gz`，列个清单能把界面卡住几十秒。
所以 `MAX_TAR_BYTES = 800MB`：超过就返回
「文件过大（超过 800 MB），未读取内容清单」。

另外成员数量也要设上限（`MAX_MEMBERS = 20000`），
超过就停并置 `truncated = True`，界面可以补一句「仅统计前 20000 项」。

### 2.4 类型构成要复用现有配色，不要自己配色

大文件页现有的 `_big_bars_from_ext()` 已经有一套做法：把 `{扩展名: [字节, 个数]}` 交给
`core/knowledge.py` 的 `filetypes().group(...)`，**分类名和颜色都由它派生**。

本卷必须走同一条路：

```python
ft = filetypes()
items = []
for cid, (size, count) in ft.group(result["exts"]):
    cat = next((c for c in ft.cats if c["id"] == cid), ft.fallback)
    items.append((cat["name"], cat["color"], size, count))
self.arch_bars.set_items(items, total)
```

自己手写一份「视频 / 图片 / 文档」的对照表，就是 v3.27 那条教训（手写必然和真实取值脱节）。

## 四、改动清单

### 4.1 `core/archive.py`（已在工程，跑过实测）

完整实现见文件本身，这里说明它的对外契约。

```python
ARCHIVE_EXTS = {
    ".zip", ".whl", ".jar", ".apk",
    ".tar", ".tar.gz", ".tgz", ".tar.bz2", ".tbz2", ".tar.xz", ".txz",
}
UNSUPPORTED_EXTS = {".rar", ".7z", ".cab", ".iso", ".lz", ".arj"}
MAX_MEMBERS = 20000
MAX_TAR_BYTES = 800 * 1024 * 1024
```

| 函数 | 说明 |
| --- | --- |
| `ext_of(path)` | 取后缀，**特判 `.tar.gz` 这类双后缀** |
| `is_archive(path)` | 是否在 `ARCHIVE_EXTS` 里；不在就不往下走 |
| `peek(path, top=8, max_members=...)` | 核心：返回清单字典，或 `None`（不该我管） |

`peek()` 返回的字典：

| 键 | 含义 |
| --- | --- |
| `kind` | 后缀，如 `.zip` / `.tar.gz` |
| `members` | 文件成员数（**目录不计**） |
| `total` | 所有成员解压后的总字节 |
| `compressed` | 压缩后字节（zip 是成员和；tar 是整个文件大小）；算不出为 `None` |
| `top` | `[(成员名, 字节), ...]`，按体积降序，最多 8 条 |
| `exts` | `{扩展名: [字节, 个数]}`，**给 TypeBars 用** |
| `truncated` | 是否撞到了 `MAX_MEMBERS` |
| `encrypted` | zip 里是否有加密成员（`flag_bits & 0x1`） |
| `size_on_disk` | 压缩包本身在磁盘上占多少 |
| `error` | 不支持 / 过大 / 读取失败的原因；正常时为 `None` |

**实测结果**（2026-10-17，构造样例跑的）：

```
sample.zip     kind=.zip     members=5  total=120100  comp=177   err=None
               top=[('video/big.mp4', 50000), ('照片/合影.jpg', 40000), ...]
               exts={'txt':[100,1],'mp4':[80000,2],'jpg':[40000,1],'(无扩展名)':[0,1]}
sample.tar.gz  kind=.tar.gz  members=3  total=16010   comp=300   err=None
dummy.rar      kind=.rar     members=0  total=0      comp=None  err=暂不支持 .rar 格式
<
stdin>                       -> None（不是压缩包，不该本模块管）

ext_of 双后缀 -> .tar.gz  .tar.xz  .zip
is_archive    -> True(zip)  False(rar)  False(.py)
```

四个要照做的设计点：

1. **`peek()` 绝不抛异常**。任何异常都在出口处被捕获并转成 `error` 字段 ——
   详情面板少一块内容可以，界面崩了不行。
2. **目录成员不计入**：`info.is_dir()` / `m.isfile()` 两个 bool 判断不能省，
   否则 `members` 会把 `photos/` 当成文件数进去。
3. **`.whl` / `.jar` / `.apk` 本质是 zip**，走 zip 分支，别漏了这几个后缀。
4. 加密成员只是**标记**（`encrypted=True`），**不去读内容** ——
   `infolist()` 本身不需要密码，一旦调 `zf.read()` 就会抛 `RuntimeError`。

### 4.3 两个新方法

```python
    def _arch_bars_from_ext(self, exts, total):
        """把压缩包里的扩展名统计画成条形图。

        配色和分类名全部走 knowledge.filetypes()，与「类型构成」那一块一致，
        不自己写对照表（v3.27 教训）。
        """
        from core.knowledge import filetypes
        if not exts:
            self.arch_bars.set_items([], 0)
            return
        ft = filetypes()
        items = []
        for cid, (size, count) in ft.group(exts):
            cat = next((c for c in ft.cats if c["id"] == cid), ft.fallback)
            items.append((cat["name"], cat["color"], size, count))
        self.arch_bars.set_items(items, total or 1)

    def _fill_archive_detail(self, full):
        """选中项是压缩包才去读清单，否则把这一块藏起来。"""
        from core import archive
        from core.sizefmt import fmt_size
        parts = (self.lb_arch_title, self.lb_arch_sum,
                 self.arch_bars, self.lb_arch_top)
        if not archive.is_archive(full):
            for w in parts:
                w.hide()
            return
        r = archive.peek(full)
        for w in parts:
            w.show()
        if r is None or r.get("error"):
            self.lb_arch_sum.setText(r.get("error") if r else "")
            self.arch_bars.set_items([], 0)
            self.lb_arch_top.setText("")
            return
        txt = f"共 {r['members']} 个成员 · 解压后 {fmt_size(r['total'])}"
        cmp_ = r.get("compressed")
        if cmp_ and r["total"]:
            ratio = int((1 - cmp_ / max(r["total"], 1)) * 100)
            txt += f" · 压缩率 {ratio}%"
        if r.get("encrypted"):
            txt += " · 含加密成员"
        if r.get("truncated"):
            txt += " · 仅统计前 20000 项"
        self.lb_arch_sum.setText(txt)
        self._arch_bars_from_ext(r["exts"], r["total"])
        if r["top"]:
            n, s = r["top"][0]
            self.lb_arch_top.setText(
                f"最大的成员：{os.path.basename(n) or n}　{fmt_size(s)}"
                + (f"（{len(r['top'])} 项，仅显示最大）" if len(r["top"]) == 8 else ""))
        else:
            self.lb_arch_top.setText("")
```

> `hide()` / `show()` 而不是塞掉 text —— 保持布局稳定，
> 选中普通文件时这一块应该**完全不存在**，不是留一片空白。

## 七、常见错误

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 选中 rar 时界面闪退 | `peek` 抛了异常 | 本模块出口已经 try 包住；**别在外面再包一层吞掉 error** |
| 成员数比实际多 | 目录也算进去了 | `info.is_dir()` / `m.isfile()` 判断不能省 |
| `.tar.gz` 被当成未知格式 | 只用了 `splitext` | `ext_of()` 必须先判三个双后缀 |
| 大 tar 卡死界面 | 没设 `MAX_TAR_BYTES` | tar 是流式的，必须限体积 |
| 条形图颜色怪 | 自己手写了分类表 | 走 `filetypes().group()`，见 2.4 |
| 中文成员名乱码 | 没影响，本卷只读名字 | zip 若设了 UTF-8 flag 会自动处理；不做额外转码 |
| 一打开大文件页就有一块空白 | 忘了初始 `hide()` | 见 4.4 的 ⚠️ |
| 离屏断言永远 False | 用了 `isVisible()` | 改用 `not isHidden()` |
