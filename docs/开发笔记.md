# YYYCleanSweep 开发笔记

面向改代码的人。用户向的说明在 [README](../README.md)。

---

## 一、分层

严格两层，**core 不认识 Qt，ui 不直接碰磁盘**。

| 层 | 目录 | 职责 | 约束 |
|---|---|---|---|
| 内核 | `core/` | 扫描、统计、去重、删除、日志、配置、知识库 | 纯 Python，可脱离 Qt 单独跑（`core/scanner.py` 就是这么用的） |
| 界面 | `ui/` | 页签、自绘控件、主题 | 只调 core 的函数，不自己 `os.walk` |
| 数据 | `rules/*.json` | 清理规则、目录知识库、文件类型 | 可编辑，程序优先读 exe 旁的同名文件 |

core 各模块一句话职责：

- `paths.py` —— 数据放哪（唯一入口，四个模块共用）
- `rules.py` —— 读 `clean_rules.json`，把规则解析成真实路径（含切盘重定向）
- `scanner.py` —— 算每条规则占多大，多线程；`find_large_files` 单独给大文件页用
- `cleaner.py` —— 三种删除模式（回收站 / 备份 / 永久），逐条统计 + 写日志
- `dirstat.py` —— 多线程按层建目录树，支持「对某个目录再挖深」
- `dupfinder.py` —— 重复文件：大小分组 → 可选内容校验 → 挑保留者
- `knowledge.py` —— 目录作用知识库，匹配不到时给兜底推断
- `marks.py` —— 白名单 / 备注，子目录继承上级
- `config.py` —— 配置 + 清理历史，原子写盘
- `journal.py` —— 每次清理动了哪些路径（纯文本，供回溯）
- `sizefmt.py` —— 全局统一的容量 / 百分比格式化
- `sound.py` —— 现场合成 WAV，winsound 播放
- `system.py` —— 系统信息（不依赖 PowerShell）
- `version.py` —— 版本号、更新说明、反馈说明、隐私说明

## 二、数据流

```
扫描：  规则/目录 → Scanner/DirTree/DupFinder（QThread）→ 结果 dict → 刷列表
决策：  结果 + 筛选条件 → 勾选集（界面负责，core 不管）
清理：  勾选集 → Cleaner.clean() → 统计 + Journal 日志 → 总结报告弹窗
```

两条容易踩的规矩：

1. **去重页的状态必须整体重算**。改了任一筛选条件就重跑 `_auto_select()`，
   不要就地打补丁——v3.21 修的「列表刷新了左下角总结没刷新」就是两套文案
   各写各的造成的。现在只有 `_update_stat()` 一处写总结。
2. **扫描一律走 QThread**，UI 线程不干重活。扫描条（ScanBanner）上的「停止」
   靠 `should_cancel` 回调接进去，取消后已扫到的部分照常显示。

## 三、界面约定（改界面前先看这段）

这些是踩过坑才定下来的，别退回老写法：

- **选中效果**由 `RowDelegate` 自绘（圆角底 + 左侧色条），不要用 QSS 的
  `border-left`——那样一选中文字就会右移。
- **圆角**容易被子控件啃成方形：列表视口要透明、表头首尾单独切圆角、
  输入框的上下/下拉/清除按钮不能铺底色。
- **主题切换**必须推送到每一个页面（`on_theme`），而且要在页面创建之后再刷一次，
  否则亮色启动时自绘控件拿的还是暗色调色板。
- **列宽**：`FirstColFit` 负责「多余宽度给第一列」，双向伸缩（拉宽变宽、缩窄收回），
  其余列各有最小宽度保底。
- **音效**用 `core/sound.py` 现场合成，分级（primary/danger/toggle/tab…），
  不放 QtMultimedia。
- **文案**照抄需求原文，方位就是字面方位（「右侧」= 同一行右边），不要自行优化措辞。
- **一个数据源、两处视图要同源**：目录分析页的树表与方块图看的是同一棵树，取
  「一个目录下要展示哪些子节点」必须走同一个入口——树表用 `_sorted_children()`，
  方块图通过 `TreemapView.kids_fn` 指回 `dir_page._treemap_kids()`（内部就是前者 +
  「只看大于 / 隐藏已标记」）。**别让方块图自己去问 `tree.children()`**，否则页面上的
  排序 / 筛选开关会只对树表生效。改完记得 `_rebuild()` 末尾对正在显示的方块图重铺一次。
- **排序权重存 `UserRole`，别靠显示文本反查**：清理页的「风险」列点表头排序，
  权重在建行时写进第 1 列 `UserRole`（`_clean_sort_key` 优先读它）——因为白名单项与
  子项根本没有风险文本。权重表本身也从 `core.rules` 的 `RISK_ORDER` / `RISK_LABEL`
  派生，禁止再手写一份文案对照表（曾因此与真实文案脱节，排序静默失灵）。
- **排序 key 一律「正分 + `reverse=desc`」**：`HeaderSorter` 对首列之外的列默认降序，
  写成负分再手动 reverse 会让「无数据项（0 分）」在降序时浮到最上面。
- **多层树要标明「当前在哪一支」**：目录分析页与大文件页的树一律用
  `ui.widgets.PathTreeWidget`（普通 `QTreeWidget` 的替代品，接口完全一致）。
  它在 `paintEvent` 里先让树自己画完，再叠加一条「选中项 → 父 → … → 根」的
  强调色折线（末端一个圆点标当前行）；选中 / 展开变化靠信号触发重绘。
  两个坑：**`visualItemRect()` 返回的行矩形已经带缩进**（顶层也占一格），
  层级线 x = `rect.x() + indentation()/2`，**不要再乘层深**（曾因此整条线偏一层）；
  主题色由 `refresh_delegates()` 顺带推给它（`_PATH_TREES` 弱引用集合）。
- **开始新一轮扫描前先清空右侧详情**：列表已经 `clear()`、详情还挂着上一轮的内容，
  会被读成「这是新扫出来的」。四个页面各有 `_clear_detail()` / `_clear_big_detail()`，
  在 `start_scan` 里调用（「继续扫描」不清——那时已扫到的行还在，详情仍有效）。
- **缓存类信息要给单位、给位置**：`fmt_bytes()` 只出千分位数字、没有单位，
  直接显示会被当成字节数瞎猜；统一写成「占用 40 KB（40,960 字节）」，
  并摆出缓存文件路径（`core/cache.db_file()` / `core/thumbs.db_file()`）+
  「打开位置」按钮（`explorer /select,`）。
- **说明性富文本走 `about.rich()`**：它支持四个轻标记
  `<b>强调</b>` / `<w>留意</w>` / `<k>放心</k>` / `<m>文件名·路径</m>`，
  先 `esc()` 再把标记换回样式，所以路径里的 `& < >` 不会截断文档。
  `core/version.py` 的文案就是用这套标记写的，**别再改成 `esc(x)` 直接渲染**——
  那会把这些标记原样显示成字面 `<b>`。
- **关于页的外链要可点**：`about.py` 的 `_browser()` 已开 `setOpenExternalLinks(True)`，
  链接地址集中成 `REPO_URL` 常量（GitHub 仓库地址），改仓库地址只动这一处。
  富文本里写 `<a href='{REPO_URL}'>…</a>` 即可，不要用 `esc()` 包住整个 `<a>`。

## 四、编码约定

- **注释与文档一律中文**（含 docstring、行内注释、提交说明）。
- 模块顶部写 docstring 说明「这个模块干什么、为什么这么设计」，
  公共函数写清参数与返回值，非平凡分支写一行为什么。
- 容量显示统一走 `core/sizefmt.py`，不要再写第二份 `fmt_size`。
- 配置键集中在 `core/config.py` 的 `DEFAULTS`，新增字段必须同时补默认值。
- 数据目录统一走 `core/paths.py` 的 `store_dir()`，不要各模块自己拼 `%APPDATA%`。
- 写盘一律「先写 .tmp 再 `os.replace`」，避免写一半断电留下半个文件。
- 页面的骨架别各写一份：主布局用 `ui/widgets.page_layout(self)`，
  顶部那条卡片行用 `ui/widgets.top_bar()`（返回 `(容器, 水平布局)`）——
  三页外观参数必须同源，否则翻页签时条高会跳。

## 六、构建与部署

```bat
build.bat          :: 入口（必须纯 ASCII，中文提示交给 build.py 打印）
```

内部是 `build.py`：

1. 单文件版（onefile，**发布产物**）与目录版（onedir，启动快）各构建一次；
   任一版失败不影响另一版，整体退出码只看单文件版。
2. 构建完部署到 `E:\work\WB_\YYYCleanSweep\app\`，旧目录版改名为
   `_old_Fast_vX.Y` 备份而不是直接删。
3. **会把工程里的 `rules\*.json` 覆盖同步到 `app\rules\`**——程序优先读 exe 旁的
   `rules\`，不同步的话新版知识库永远不生效。

已知坑：

- 旧 exe 还在运行会覆盖失败（报错里会提示先退出程序）。
- `build.py` 会先删同名旧构建目录，文件一多可能撞上环境的批量删除保护、
  整套构建被中止——把旧目录改名（如 `_bak01`）后重建即可。

## 七、目录知识库怎么扩充

`rules/dir_knowledge.json` 的条目结构：

```json
{"id":"...", "name":"...", "names":["小写全等匹配"], "paths":["路径后缀"],
 "parents":["父目录名"], "keywords":["路径关键词"], "container":false,
 "kind":"cache|settings|data|install|log|system|user|game|temp|backup|model|db",
 "risk":"safe|caution|migrate|keep|danger", "purpose":"干什么用", "advice":"怎么处置"}
```

匹配优先级：`paths` > `parents + names` > `names` > `keywords`。

扩充流程：写 `_kb_new*.py`（里面 `NEW = [dict(...)]`）→ 跑 `_kb_merge.py`
（按 id 去重；names 被原库占用的会被剔除或整条跳过）。

经验教训：

- **不要用过于通用的 name**。曾用 `EldenRing` 导致 Roaming 下的存档被 MOD 条目抢走。
- 游戏存档一律 `risk=keep`。

**这一轮攒下的硬经验**（都在 `MEMORY.md` 里留了档，改代码前先看一眼）：

1. **windowed exe 没有控制台**：两个 spec 都是 `console=False`，`sys.stdout` 是 None，
   `print()` 静默失败。命令行输出必须 `AttachConsole(-1)` 借父进程窗口，失败才
   `AllocConsole()`，并 `SetConsoleOutputCP(65001)`。
2. **`.bat` 三条铁律**：纯 ASCII、CRLF、绝不出现 `chcp 65001`（注释里也别写字面）。
   裸 LF 会让 cmd 砍掉命令首字母（`set`→`et`），chcp 会让批处理当场终止。
3. **dHash 对裁剪极敏感**：缩放、转发压缩距离 0~3；裁掉 5% 边缘距离跳到 16。
   这是算法固有局限，UI 上必须写清楚，不能靠调阈值解决。
4. **路径比较前先归一化**：`replace("/", "\\")` + 折叠连续分隔符，否则
   `C:\Windows\Web\Wallpaper` 这类排除规则会跨环境静默失效。
5. **`hex_alpha()` 与 `with_alpha()` 别混用**：前者返回 `rgba(...)` 字符串只给 QSS，
   后者返回 `QColor` 给 QPainter；把字符串塞进 `QColor()` 会静默画成纯黑。
